# SFT 数据集数据清洗规范总结

> 适用场景：图片创作助手两阶段推理任务（Memory 维护 + Sug 生成）的 SFT 训练数据质量管控。

---

## 一、清洗目标

确保进入 SFT 训练集的样本：
- **格式合规**：严格符合预设的输出契约（think / decision / memory 等结构）。
- **语义纯净**：不含 teacher 模型的元推理、重试过程、自我修正等中间产物。
- **状态自洽**：多轮 memory 演进链路逻辑一致、无前后矛盾。
- **文本质量**：无超长、重复、循环等退化文本模式。

---

## 二、核心清洗规则

### 2.1 上下文泄漏类

| 问题 | 说明 |
|------|------|
| **Teacher 校验重试上下文泄漏** | UID 中混入了 teacher 模型在生成过程中的校验/重试痕迹，例如"上次输出失败""修复上一版"等表述。这类内容会让模型学到不应出现在推理链中的元话语。 |

### 2.2 推理过程污染类

| 问题 | 说明 |
|------|------|
| **英文元推理** | think 中出现英文的元推理/自我对话内容，与目标中文推理风格不一致，属于 teacher 生成过程中的语言泄漏。 |
| **额外 `<think>` token 序列** | think 区域中嵌套了多余的 think 标签或 token，破坏了推理过程的单层结构。 |
| **think 标签结构歧义** | think 标签的开闭不匹配、嵌套层级不清或格式不统一，导致解析器无法正确识别推理边界。 |

### 2.3 状态一致性类

| 问题 | 说明 |
|------|------|
| **Memory 状态链不一致** | 多轮样本中 memory 的前后状态演变不符合逻辑——例如旧兴趣条目凭空消失、次数/天数只减不增、首次日期变晚等，违反了"只增不减、首次不晚于最近"的硬约束。 |
| **Memory 状态受污染** | memory 正文中混入了 Markdown 格式标记、模型自述文字、或非结构化的自由文本，破坏了固定槽位（6 槽 + 2 页脚）的结构化契约。 |

### 2.4 输出契约类

| 问题 | 说明 |
|------|------|
| **未通过最终输出契约** | 最终输出不满足预设的格式检查清单：固定槽不全、兴趣条目缺少强度/次数/天数/日期字段、缺少 ADD/MERGE/UP/DOWN/STAY/EVICT/KILL 操作声明、[可推荐] 数量不达标等。 |
| **生成失败样本** | teacher 在生成过程中发生截断、重复、JSON 解析失败等异常，输出不完整或不可解析。 |

### 2.5 数据完整性类

| 问题 | 说明 |
|------|------|
| **不可恢复的编码损坏** | 文本出现乱码、UTF-8 解码错误、特殊字符损坏等，无法通过后处理修复，必须整条丢弃。 |

### 2.6 文本质量类

| 问题 | 说明 |
|------|------|
| **超长样本** | 文本长度显著超出预期分布（如 think 或 memory 过长），可能导致训练时截断或梯度异常。 |
| **重复 Title/Desc** | 同一 UID 内或跨 UID 出现几乎逐字相同的标题/描述内容，降低数据多样性。 |
| **n-gram 循环** | 文本中出现连续的 n-gram 片段重复循环（如"汉服 汉服 汉服..."），是典型的模型生成退化特征。 |
| **连续字符循环** | 出现"aaaa""----"等单字符/短 token 无限重复的退化模式。 |

### 3.1 分层清洗体系

清洗规则不是平铺罗列，而是按**问题根源逐层递进**：

```
语义层（上下文泄漏 / 元推理污染）
    ↓
结构层（think 标签结构 / 槽位完整性）
    ↓
逻辑层（memory 状态链一致性 / 操作声明完整性）
    ↓
语法层（编码损坏 / 格式契约校验）
    ↓
文本质量层（长度 / 重复 / 循环退化）
```

这种分层设计的好处是：上游问题一旦识别即可提前丢弃，不必进入下游昂贵的规则校验，同时每一层都有明确的失败原因标注，便于后续归因分析。

### 3.2 针对多轮推理任务的专项校验

本任务是**两阶段推理**（先更新 memory，再基于 memory 生成 sug），因此清洗规则深度绑定了任务特性：

- **状态链追溯**：不是孤立检查单条样本的格式，而是追溯整个 memory 演进链的前后一致性，确保"次数只增、天数只增、首次不前移、最近不后退"等不变量成立。
- **操作声明审计**：要求每次更新必须显式声明 `ADD / MERGE / UP / DOWN / STAY / EVICT / KILL`，任何未声明的旧条目消失都视为违规——这是一种**可追溯的变更管理思维**，类似于数据库的变更日志。
- **槽位契约校验**：固定 6 槽 + 2 页脚的结构，每个槽有明确的字段格式和数量上限，通过结构化校验而非模糊匹配来保证输出稳定性。

### 3.3 Teacher 数据的"去过程化"原则

这是 LLM SFT 数据清洗中非常关键的专业做法：

- **只保留最终正确输出，丢弃中间推理痕迹**：teacher 模型在校验失败后重试的过程、自我修正的元话语、"让我再想想"类的过渡语句，都不属于学生模型应该学习的推理模式。
- **防止元推理泄漏**：英文元推理、额外 think 标签的剔除，本质上是在做**训练目标对齐**——学生模型应该学习的是"任务推理"，而不是"关于推理的推理"。
- **Few-shot 示例的污染控制**：明确要求"实际作答必须重新判断，禁止复制示例内容"，避免 teacher 把 few-shot 中的示例数据直接抄进输出。

### 3.4 文本退化模式的主动检测

除了常规的格式和逻辑校验，还专门针对 LLM 生成文本的典型退化模式设置了过滤规则：

- **n-gram 循环检测**：识别模型陷入重复循环时产生的 n-gram 级重复。
- **连续字符循环检测**：捕获最极端的 token 退化。
- **重复 Title/Desc 去重**：在语义级别而非字符级别识别近义重复，确保候选提案的多样性。

### 3.5 与 RL 阶段的数据隔离原则

虽然本文聚焦 SFT 清洗，但文档中同步体现了跨阶段的数据质量意识：

- **SFT 与 RL 数据集不同源**：避免训练-评估数据泄漏导致 RL 指标虚高。
- **丢弃全对全错/分数一致样本**：在 RL 标注阶段主动剔除信息量低的样本，提高标注效率和奖励信号质量。
- **标注一致性检验（Kappa 系数）**：用统计指标而非人工直觉来把控标注质量。
- **防止表面奖励 / Reward Hacking**：格式奖励适度设计，避免模型只学到格式/长度模式而忽略实质内容。

## 五、总结

本套数据清洗规范的核心专业特征可以概括为三点：

1. **任务感知（Task-aware）**：清洗规则不是通用文本过滤，而是深度绑定两阶段推理任务的结构（Memory 槽位、操作声明、状态演进不变量），确保训练数据在语义和逻辑层面真正可用。
2. **过程去污染（De-proceduralization）**：严格剥离 teacher 模型生成过程中的中间痕迹、元推理和自我修正，只保留"干净的"最终推理轨迹，避免学生模型学到错误的推理模式。
3. **可追溯性（Traceability）**：通过操作声明（ADD/MERGE/EVICT/KILL）、变更原因标注等机制，让每一条数据的"变更历史"可审计，这在多轮记忆类任务的 SFT 数据建设中是较高阶的实践。
